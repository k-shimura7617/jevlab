# jevlab 伴走ガイド

起動済みの jevlab を自分で操作しながら、機能を 1 つずつ掴むための手順書です。

- 画面: http://127.0.0.1:5173（`scripts/dev.sh`）／ http://127.0.0.1:8000（ビルド版）
- 件は件名で指します。T 番号は「受付箱を空にする」と振り直されるので、あくまで例です。
- 分類が Jev のときは、1 件あたり約 $0.0001 かかります。右上の「Jev 利用額（目安）」で確かめられます。
- 実際の Slack とつなぐ手順は [slack-setup.md](slack-setup.md) にあります。つながなくても、管理画面の疑似 Slack で試せます。

**画面の分け方**（[ADR-0030](adr/0030-user-screens-and-admin.md)）
- 利用者（CS 担当・リーダー）のメニュー: 受付箱・対応待ち・成績・設定（取り込みは設定のタブ）。
- 管理（`/admin`、開発側）: 処理の状況・詳細設定・個人情報の判定・コネクタ・疑似 Slack・監査ログ。左のメニューの「管理」から開く。

| # | 項目 | 画面 |
|---|---|---|
| 0 | 準備 | 管理 → 処理の状況 |
| 1 | 受信と自動の流れ | 運用（入口）・受付箱 |
| 2 | 個人情報の確認 | 対応待ち |
| 3 | 分類の確認 | 対応待ち |
| 4 | エスカレーション | 対応待ち |
| 5 | Slack への投稿 | 管理 → 疑似 Slack |

| 7 | 成績 | 成績 |
| 8 | 設定 | 設定 |
| 9 | 管理画面 | 管理 |
| 10 | 評価ダッシュボード | 評価ダッシュボード |

## 0. 準備

**手順**
1. http://127.0.0.1:5173/admin を開く（管理画面の「処理の状況」）。
2. 受信シミュレータの「受付箱を空にする」を押し、OK を押す（設定と担当者は残る）。
3. 「最初から」を押す。

**確かめること**
- 処理フローの件数がすべて 0。
- シミュレータに「0 / 64 件」と出ている。

---

## 1. 受信と自動の流れ

**手順**
1. 管理画面のシミュレータで間隔を「2 秒ごと」にし、「▶ 受信を開始」を押す。流したら「⏸ 一時停止」を押す。
2. 左のメニューの「運用ダッシュボード」を押す。入口に「対応が必要な問い合わせ N 件」と内訳、その下に処理フロー（受信 → ガードレール → 仕分け → 振り分け → 完了）が出る。
3. 「受付箱」で 1 件をクリックし、右の「経過（監査ログ）」を上から読む（受信 → 個人情報 → 分類 → 行き先）。
   - 「担当者」で絞れる。Slack のリンクから開くと、その件の担当者で絞った状態になる。
   - 完了した件は「完了を表示」で出る（既定はオフ）。

**確かめること**
- 入口の件数と、受付箱のタブの件数が合っている。
- 対応が必要な問い合わせがなければ、入口に「すべて対応済みです」と出る。
- 受付箱と対応待ちの画面は、一覧と詳細が画面の下端まで伸び、中でスクロールする。

**分かること**
- 個人情報のある件は、Jev に送る前に人の確認で止まる。
- 確信度が自動の閾値（既定 0.9）以上なら自動で振り分け、0.5 以上なら分類の確認、それ未満や緊急・強い不満ならエスカレーション。順番は [ADR-0029](adr/0029-route-order-table.md)。

## 2. 個人情報の確認

| タグ | 意味 |
|---|---|
| 検出済み | 個人情報がすべて確定している（最初からチェック済み） |
| 未確定の候補 | 個人情報かどうかを自動では決めきれなかった候補がある |
| 見落としの可能性 | ほかにも残っているかもしれない |
| 編集あり | 右側での編集が保存されている |

**手順**
1. メニューの「対応待ち」を押す。件のあるいちばん手前のタブ（個人情報の確認 → 分類の確認 → エスカレーション）が開く。
2. 件名「返金がされていません」を開き、表の「松本 恵」の「個人情報」にチェックを入れる。
   - プレビューが【氏名】になり、ボタンが「マスクして仕分け（1 箇所）」になる。
   - 別の件を開いて戻っても、チェックが残る。一覧に「編集あり」が付く。
3. 見落としがあれば、本文を選択 → 種類を選ぶ →「個人情報として追加」を押す。
4. 件名「二重に引き落とされています」は「ブロック（Jev に送らない）」だけになる。押すと Jev を通さずにエスカレーションへ回る。
5. 左の一覧でチェックを入れ、帯のボタンでまとめて処理する。

**分かること**
- 電話・メール・カードなど、形で決まる種類は規則で確定する。氏名だけを Kev に聞く。
- 編集していない件をまとめて処理すると、候補をすべて伏せる（安全側）。
- Jev に届くのは、プレビューの伏せ字の本文だけ。

---

## 3. 分類の確認

**手順**
1. 対応待ちの「分類の確認」タブを開く。
2. 1 件を選び、右の分類の確率を見る。
3. キーで確定する。`1`〜`4`: 問い合わせ／クレーム／お礼／その他。`j` / `k`: 次・前の件。

**確かめること**
- 確定した件が一覧から消え、次の件が開く。
- 一覧は届いた順（古い順）。

**分かること**
- 人の確定が、成績（項目 7）の正解になる。

---

## 4. エスカレーション

**手順**
1. 対応待ちの「エスカレーション」タブを開く。
2. 1 件を選び、担当者を決める（推定があれば「この担当にする」）。
3. メモを書いて Enter を押す（日本語入力の変換を確定する Enter では追加しない）。
4. 「返信内容の検討」を押す。返信前チェックが開く。右上の件 ID を押すと、この画面の同じ件に戻る。
5. 「最終の分類」を選び、「対応完了にする」を押す。次の件が開く（受付箱には移らない）。
6. 帯の担当者の欄で 1 人を選び、チェックを足したり外したりして、まとめて割り当てる。

**確かめること**
- 完了は、エスカレーションの投稿のスレッドへの返信（メモ付き）と ✅ で知らせる。分類のチャンネルには投稿しない。
- 完了済みの件を Slack のリンクから開くと、受付箱でその件が開く。

**分かること**
- 担当の推定は分類と同じ 1 回の問い合わせで行うので、追加料金はほぼない。
- 推定した担当の確率が 0.7 以上なら自動で割り当てる。届かないときも、確率が一番高い人に仮で割り当てる。
- 個人情報のためブロックした件には、Kev による参考の分類と担当の推定が付く。自動では振り分けない。

---

## 5. Slack への投稿

**手順**
1. 管理画面の「疑似 Slack」を開く。
2. #cs-問い合わせ／#cs-クレーム／#cs-お礼／#cs-その他／#cs-エスカレーション を順に開く。
3. 「#お問い合わせ窓口」に 1 行書いて「送信」し、受付箱に届いたことを確かめる。

**確かめること**
- 投稿に差出人の名前が載っていない。見出しは個人情報の候補をすべて伏せている。

**分かること**
- 実際の Slack にも流せる（設定 → Slack。手順は [slack-setup.md](slack-setup.md)）。#お問い合わせ窓口（元の本文）は流さない。
- 投稿の形: 1 行目にメンション、次に見出しと「画面で開く」、空行のあとに「対応お願いします。」と担当確信度。担当が未定なら、振り分け担当に「担当を決めてください。」と推定を書く。
- 担当を変えたとき・完了したときは、その投稿のスレッドに書く。完了すると投稿に ✅ が付く。
- 返信のいらない分類（お礼など）は、投稿してスレッドに「対応不要のため完了にしました。」と書き、✅ を付ける。メンションはしない。

---

## 6. 振り分けた件を完了にする

**手順**
1. 受付箱で「振り分け済み」の件を開く（Slack の「画面で開く」からでもよい）。
2. 分類が合っていれば、そのまま「対応完了にする」を押す。違っていれば、正しい分類に切り替えてから押す。

**確かめること**
- 完了すると、「完了を表示」がオフなら一覧から消える。右の詳細は開いたまま。

**分かること**
- 触らずに完了した件は「分類は合っていた」、切り替えた件は「修正した」として、成績の正解に数える。
- 自動で完了にした件は、件の詳細の「自動の完了を取り消す」で振り分け済みに戻せる。
- 差出人のアドレスがある件は、「メールで返信」で宛先と「Re: 件名」を入れたメールソフトが開く（jevlab はメールを送らない）。

---

## 7. 成績

**手順**
1. メニューの「成績」を開く。
2. 「分類」の表を見る（行: Jev の予測、列: 人が確かめた分類。右端が正解率）。
3. 「自動で振り分ける確信度」のカードで、おすすめといまの値を比べる。
4. おすすめのあるカードで「おすすめに合わせる」を押す（その場で反映される）。
   - 「全体」は共通の値を、分類ごとのカードはその分類の値を変える。
   - 人が確かめた件が 20 件に満たないと、おすすめは出ない。
5. 「担当の推定」で、推定と実際の担当の一致を見る。

**分かること**
- 正解は、人が確かめた件（分類の確認で確定・完了した件）だけ。誤り 5% 以下になるいちばん低い値をおすすめする。
- 値を下げると自動が増えて人の手間が減るが、誤りも増える。

## 8. 設定

**手順**
1. メニューの「設定」を開く。「分類」「担当者」「Slack」「取り込み」のタブがある。
2. 「分類」タブ
   - 「分類とチャンネル」で「＋ 分類を追加」を押し、分類名・説明・チャンネル（例: 配送／配送の遅れ・破損／#cs-配送）を入れる。
   - 「振り分けた後」を選ぶ: 担当に回す／対応不要として完了／対応が要るかを Jev が判断。
   - 試したら「削除」で消す。使ったことのある分類は「削除した分類」に残り、「戻す」で戻せる。
   - 「自動で振り分ける確信度」を動かす。分類ごとの値（成績で変えたもの）は「共通の値に戻す」で戻せる。
   - 「個人情報」: 「氏名などを Kev で判定する」「見つけたら人が確認する」のオンオフ。
3. 「担当者」タブ: 名前・担当範囲・Slack ID・担当のオンオフ。完了が 10 件以上ある人は「完了 N 件から案を作る」で担当範囲の案を作れる。
4. 「Slack」タブ: 送信・受信・振り分け担当・投稿先のチャンネル ID。

**確かめること**
- 変更は自動で保存される（文字の欄とスライダーはカーソルが外れたとき、チェック・選択は変えたとき）。
- チャンネルに、受信用とエスカレーションのチャンネルは指定できない。ほかの分類と同じチャンネルも不可。

**分かること**
- 設定は、次に処理する件から効く。
- 細かい値（確認待ちの閾値・不満や緊急の扱い・個人情報の方針など）は管理画面の詳細設定にある。利用者には出さない。

## 9. 管理画面

左のメニューの「管理」から開く。

| タブ | 中身 |
|---|---|
| 処理の状況 | 受信シミュレータ、お客様としてメールを送る、指標、最新の動き |
| 詳細設定 | 個人情報のガードレール（接続先・確率・種類ごとの方針・ブロックした件）、仕分け（接続先・確認待ちの閾値・業務ルール）、Kev で先に判定、担当の自動の割り当て |
| 個人情報の判定 | Kev の判定と人の確認の突き合わせ、検知漏れの報告の集計 |
| コネクタ | 受信経路の接続、Slack の投稿の全削除、API の例 |
| 疑似 Slack | 画面上のチャンネル |
| 監査ログ | CSV の書き出し |

**ファイルで取り込む**（設定 →「取り込み」）
1. 「ファイル取り込み」に、CSV（UTF-8・Shift_JIS）、Excel（.xlsx）、メール（.eml・.mbox）、Slack のエクスポート（.zip）を入れる。
2. 列の対応と「過去の分類の対応」、先頭 5 件を確かめ、「N 件を取り込む」を押す。同じ画面に「N 件を取り込みました」と処理の進み具合が出る。
3. 見本は `docs/samples/import/`（すべて架空のデータ）。`大量_1000件.csv` は並列処理の速さを見るのに使う（MOCK で約 18 秒）。

**過去の問い合わせで試算する**
- 取り込むときに「完了済みの問い合わせとして取り込む」にチェックを入れると、仕分けまで行って完了にする（投稿・人の対応には回さない）。

## 10. 評価ダッシュボード

**手順**
1. 左ペインの「評価ダッシュボード」でアプリ一覧を見る。
2. 1 つ選び（例: 問い合わせ仕分け）、「ライブ評価」を開く。
3. ヘッダーを MOCK にし、件数を 5 にして「評価を開始」を押す。
4. 一致率、対応表、「不一致」の絞り込みを見る。
5. 「実行の種類」を「比較」にし、Kev と MOCK で実行する（Kev は並列 1）。
6. 「単発判定・履歴」で、自由入力の文面を判定する。

**確かめること**
- 比較の集計に「両方判定できた N 件のうち M 件が同じ」と出る。

**分かること**
- Jev と Kev の差を同じデータで数字として見られる。「Kev で先に判定」や閉域化を判断する根拠になる。
- 確信度の区分ごとの一致率で、確信度がどれだけ信用できるかを見られる。

## 11. 言い方チェック

**手順**
1. 「ツール → 言い方チェック」を開き、ヘッダーで接続先を選ぶ。
   - 相手（上司・同僚・部下・取引先・お客様・友人・家族）と場面は、既定で「指定なし」（一般的なビジネスの相手・場面として判定）。
2. 例文「言い訳の入った謝罪」を押す。
3. 「判定する」を押す（Ctrl+Enter でもよい）（Kev では約 10 秒）。
4. 総合判定、目的、印象、観点のバー、「きつく見える文」（濃いほどきつく見える）を見る。
5. 「目的」を「報告・連絡」に変え、表示の変化を見る。
6. モデル（sonnet がおすすめ、opus は微妙なニュアンス向き）を選び、「書き換え案を作る」を押す（sonnet で約 10 秒）。
7. 案を直してから「この案を判定する」を押し、比較表を見る。

**確かめること**
- 入力欄を変えると注意が出て、書き換えのボタンが押せなくなる。
- 案を編集すると、比較表に「編集前の案の比較」と出る。

**分かること**
- 判定は Jev/Kev が担い、書き換えは Claude が担う。
- 目的によって見る観点が変わる（報告では「期限が明確か」を問わない）。

## 12. 契約・規約チェック

**手順**
1. 「ツール → 契約・規約チェック」を開く。上に「法的助言ではありません」と出ている。
2. 「例: SaaS 利用規約」を押し、「判定する」を押す（Ctrl+Enter でもよい）。
3. 条項ごとの色（要見直し・注意・問題なし）と、当てはまる項目（自動更新・違約金・責任制限・データ第三者提供）を見る。
4. 「やさしく説明（Claude）」を押すと、気になる条項ごとに説明と確認するとよいことが出る（sonnet、十数秒）。

**分かること**
- 条項の数だけの質問を 1 回で判定する（6 条なら 30 問）。
- 判定は Jev/Kev、説明は Claude（言い方チェックと同じ分担）。

## 13. 返信前チェック

**手順**
1. 「ツール → 返信前チェック」を開き、「例」を押して「判定する」を押す。
2. 総合判定と、観点（質問に答えている・方針を超えた約束・きつい・素っ気ない・謝罪）、足りない情報を見る。
3. 枠の下の「方針」を押すと、モーダルで判定と AI返信案に使う方針を直せる（Esc か「閉じる」で閉じる。「？」に説明）。
4. 「AI返信案の作成」（Claude・sonnet）で案を作る。案は書いた分から順に出る（ストリーミング）。下書きがあれば判定の指摘をもとに直した案、なければ問い合わせから書いた案になる。「採用」で下書きに入れ、「この案を判定する」で下書きと比べる。
   - 生成中に「判定する」を押したり、ほかの画面へ移ったりすると「生成を中止しますか？」と出る。OK で生成を止める（Claude の処理も止まる）。
5. 運用の件の詳細（受付箱・分類の確認・エスカレーション）の「返信内容の検討」ボタンから開くと、その件の問い合わせが入る。
   - 受付の確認どおりに伏せ字にした本文で、「伏せ字済み（受付の確認どおり）」と出る。問い合わせの欄は書き換えられない。
   - 差出人のアドレスがある件は、判定した後に結果の枠の「この内容で返信」（「判定する」と同じ高さ）を押すと、宛先・「Re: 件名」・判定した下書きを入れたメールソフトが新しいタブで開く（判定の後に下書きを書き換えたら、判定し直すまで押せない）。

**分かること**
- 自由に入れた問い合わせ・下書きは、伏せずに Jev・Claude に送る（会社側の道具のため）。
  - 送る前に消したいときは「個人情報チェック」を押す。規則と Kev で調べ、「個人情報マスク」で入力欄を【種類】に置き換える（Jev・Claude には送らない）。言い方チェック・契約・規約チェックにも同じボタンがある。
- 件から開いたときの問い合わせは、サーバ側で伏せ字にしたものを使う。
- 足りない情報は、候補（注文番号・連絡する時期・お客様にお願いすることなど）ごとに「必要なのに書かれていないか」を聞く。
- 確認中の件では、返品・交換の期限や手順は「足りない」とせず、AI の案にも書かない（確認のあとに案内すると書く）。書いてよい期日は、こちらから連絡する時期だけ。

## 14. 監査ログ

**手順**
1. 管理画面の「監査ログ」を開く。
2. 期間（既定は直近 7 日）・件・種類・文字コードを選び、「CSV を書き出す」を押す。
3. 「書き出しの記録」に、日時・条件・行数が残る。

**確かめること**
- CSV に本文・差出人・メモの本文・電話番号などが出ていない。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 5173 番の画面が開かない | 1. `ps -o stat,cmd -u $USER \| grep vite` で状態が `T` なら停止中<br>2. `dev.sh` を Ctrl+C で止める<br>3. `pkill -CONT -f node_modules/.bin/vite; pkill -f node_modules/.bin/vite` を実行する<br>4. `dev.sh` を起動し直す<br>急ぐときは 8000 番を開く |
| Kev が使えない・エラーになる | 1. 運用の入口に「Kev（…）に接続できません」と出る。`curl -s 127.0.0.1:8009/v1/models` でも確かめられる<br>2. 止まっていれば Kev を起動する（`~/develop/2026/kev` で。jevlab の中では「Extra serve is not defined」になる）:<br>`(cd ~/develop/2026/kev && env -u VIRTUAL_ENV uv run --extra serve python -m kev.serve --run jaredpalmer/kev-0.8b --port 8009)`<br>3. エラーの件は、受付箱の詳細の「再実行」で流し直す<br>急ぐときは「設定 → 氏名などを Kev で判定する」をオフにして規則だけで進める |
| Kev が遅い | CPU で動くため、1 回に数秒〜10 秒かかる |
| Jev が「上限」で止まる | 1. `JEVLAB_BUDGET_USD` で上限を変える（既定 $1.00）<br>2. サーバを起動し直す |
| 表示が古い | F5 で再読み込みする |
