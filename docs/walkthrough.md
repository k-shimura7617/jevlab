# jevlab 伴走ガイド

起動済みの jevlab を自分で操作しながら、機能を 1 つずつ掴むための手順書です。

- 画面: http://127.0.0.1:5173（`scripts/dev.sh`）／ http://127.0.0.1:8000（ビルド版）
- 件は件名で指します。T 番号は「受付箱を空にする」と振り直されるので、あくまで例です。
- 分類が Jev のときは、1 件あたり約 $0.0001 かかります。右上の「Jev 利用額（目安）」で確かめられます。
- ボタン名の変更予定（まだ反映されていません）:
  - 「マスクして仕分けへ」→「マスクして仕分け」
  - 「そのまま仕分けへ」→「そのまま仕分け」

## 0. 準備と全体像

**手順**
1. http://127.0.0.1:5173 を開く。
2. 左ペインで、次の 3 つのまとまりを確かめる。
   - 運用ダッシュボード
   - 評価ダッシュボード
   - ツール
3. 運用ダッシュボードの「デモの進め方」を開き、6 ステップを眺める。
4. 受信シミュレータの「受付箱を空にする」を押し、OK を押す（設定と担当者は残る）。
5. 「最初から」を押す。

**確かめること**
- 流れ図の件数がすべて 0。
- シミュレータに「0 / 64 件」と出ている。

---

## 1. 受信と自動の流れ

**手順**
1. シミュレータの間隔を「2 秒ごと」にする。
2. 「1 件だけ受信」を 3 回押し、流れ図の動きを見る。
3. 左ペインの「受付箱」で 1 件をクリックする。
4. 右の「経過（監査ログ）」を上から読む（受信 → 個人情報 → 分類 → 行き先）。
5. ダッシュボードで「▶ 受信を開始」を押し、流したら「⏸ 一時停止」を押す。

**確かめること**
- どこに件がたまっているか。多いのは「個人情報の確認」。
- 右上の利用額の増え方。

**分かること**
- 個人情報のある件は、Jev に送る前に人の確認で止まる。
- 確信度が 0.9 以上なら自動で振り分け、0.5〜0.9 なら分類の確認、それ未満や緊急・強い不満ならエスカレーション。

## 2. 個人情報の確認（Kev）

| タグ | 意味 |
|---|---|
| 検出済み | 個人情報がすべて確定している（最初からチェック済み） |
| 氏名の可能性 | 氏名かどうかを自動では決めきれなかった |
| 見落としの可能性 | ほかにも残っているかもしれない |
| 編集あり | 右側での編集が保存されている |

**① 開く**
1. 左ペインの「個人情報の確認（Kev）」を開く。
2. 帯に「N / M 件を選択」と出ていることを確かめる。

**② 氏名を決める（件名「返金がされていません」）**
1. その件をクリックする。
2. 表の「松本 恵」の「個人情報」にチェックを入れる。
3. 帯に「編集を保存しました」と出ることを確かめる。
4. プレビューが【氏名】になっていることを確かめる。
5. ボタンが「マスクして仕分けへ（1 箇所）」になっていることを確かめる。
6. 別の件を開いてから戻り、チェックが残っていることを確かめる。
7. 一覧に「編集あり」のタグが付いていることを確かめる。
8. 右のボタンで処理するか、左のチェックを入れておいて ⑤ でまとめて処理する。
9. 元に戻したいときは、帯の「編集を取り消す」を押す。

**③ 見落としを読む（件名「こんにちは、ひだまり手づくり市の…」）**
1. その件を開き、本文を読む。
2. 個人情報がなければ「そのまま仕分けへ」を押す。
3. あれば、該当箇所を選択 → 種類を選ぶ →「個人情報として追加」→「マスクして仕分けへ」の順に押す。

**④ ブロック（件名「二重に引き落とされています」）**
1. その件を開く。
2. ボタンが「ブロック（Jev に送らない）」だけになっていることを確かめる。
3. 押すと、Jev を通さずにエスカレーションへ回る。口座番号の件（件名「ブランケットの品質について」）も同じ。

**⑤ まとめて処理**
1. 帯のボタンを押す。
   - 通常は「選んだ N 件をマスクして仕分けへ」。
   - ブロック対象を含むときは「選んだ N 件を処理（マスクして仕分け M・ブロック K）」。
2. 完了メッセージの件数を確かめる。

**⑥ 行き先を見る**
1. ダッシュボードの流れ図で、「個人情報の確認」が減ったことを確かめる。

**分かること**
- 電話・メール・カードなど、形で決まる種類は規則で確定する。氏名だけを Kev に聞く。
- 規則で確定した種類は、チェックを外しても処理のときにサーバが元に戻す。
- 編集していない件をまとめて処理すると、候補をすべてマスクする（安全側）。編集した件は、その内容で処理する。
- Jev に届くのは、プレビューの伏せ字の本文だけ。

## 3. 分類の確認（Jev）

**手順**
1. 左ペインの「分類の確認（Jev）」を開く。
2. 「確認待ち」タブで 1 件を選び、右の分類の確率を見る。
3. キーで確定する。
   - `1`〜`4`: 問い合わせ／クレーム／お礼／その他
   - `j` / `k`: 次の件・前の件
4. 「分類で絞り込む」のチップを押してみる。
5. 「並び順」を「優先度」と「受信順」で切り替える。
6. 「優先度の重み」を開き、「緊急」を最大にして並びの変化を見る（見たら戻す）。
7. 「抜き取り確認」タブで 1 件を確かめる。

**確かめること**
- 確定した件が一覧から消え、チャンネルに投稿される。
- 重みを変えると、判定し直さずに並び順だけが変わる。

**分かること**
- 人の確定と抜き取りの結果が、閾値の調整（項目 8）の正解になる。
- 重みは並び順だけを変え、Jev への問い合わせはしない。

## 4. エスカレーション

**手順**
1. 左ペインの「エスカレーション」を開く。
2. 各行の表示を見る。
   - 「⏱ 残り N 分」
   - 担当者、または「推定: ◯◯」
   - 「自動」の印
3. 1 件を選び、「担当の推定」の「この担当にする」を押す。
4. メモを書いて「追加」を押す。
5. 「最終の分類」を選び、「対応完了にする」を押す。
6. 「クレーム」で絞り込み、チェックで 2〜3 件選ぶ。
7. 帯で担当者を選び、「選んだ N 件を割り当てる」を押す。

**確かめること**
- 完了した件が、分類のチャンネルに「担当者（対応完了）」として投稿される。
- 「N 件を ◯◯ に割り当てました」と出る。

**分かること**
- 担当の推定は分類と同じ 1 回の問い合わせで行うので、追加料金はほぼない。
- 自動で割り当てるのは確信度 0.7 以上だけ。残りは人が決める。
- 人が決めて完了した件は、次からの推定の「例」になる。

## 5. チャンネル（疑似 Slack）

**手順**
1. 左ペインの「チャンネル」を開く。
2. #cs-問い合わせ／#cs-クレーム／#cs-お礼／#cs-その他／#cs-エスカレーション を順に開く。
3. 投稿の件名（伏せ字）、注文番号、投稿者を見る。
4. 「#お問い合わせ窓口」に 1 行書いて「送信」する。
5. ダッシュボードで、その書き込みが受付箱に届いたことを確かめる。

**確かめること**
- 投稿に差出人の名前が載っていない。

**分かること**
- 外に出る見出しは、個人情報の候補をすべて伏せている。
- 本番ではこの画面が実際の Slack に置き換わる（接続はやることリストにある）。

## 6. 担当者

**手順**
1. 左ペインの「管理 → 担当者」を開く。
2. 「担当範囲（Jev が読む説明）」を読む。
3. 「＋ 担当者を追加」で 1 人足し、「保存」を押す。
4. 「自動の割り当て」の設定を見る（オン・オフ、確信度 0.70、例を渡すか）。
5. 「推定の当たり具合」を見る（項目 4 で完了した件があれば出る）。
6. 追加した担当者を削除し、「保存」を押す。

**確かめること**
- 「保存しました。次にエスカレーションになる件から反映されます」と出る。
- 完了件が 10 件未満のときは「参考値」と出る。

**分かること**
- 担当範囲を重ならないように書くと、推定が当たりやすい。
- 「取り違えが多い組み合わせ」は、担当範囲を直す手がかりになる。

## 7. 手で 1 件送る・CSV で取り込む

**手で送る**
1. 「受付箱」右上の「お客様としてメールを送る」を押す。
2. 本文を入れて「送信」する（例: 「電話は 090-0000-1234 です」）。
3. 一覧で行き先を確かめる。個人情報があれば「個人情報の確認」へ進む。

**CSV で取り込む**
1. 「管理 → コネクタ」を開く。
2. 「サンプル CSV をダウンロード」を押す。
3. ダウンロードしたファイルをドロップ欄に入れる。
4. 列の対応とプレビューを確かめる。
5. 「N 件を取り込む」を押す。
6. 「受付箱で見る」で届いたことを確かめる。

**確かめること**
- コネクタを「切断」すると、その経路から受け付けなくなる。確かめたら「接続する」で戻す。

**分かること**
- どの経路から来ても、同じ流れ（ガード → 仕分け → 振り分け）を通る。

## 8. 閾値の調整

**手順**
1. 「管理 → 閾値の調整」を開く。
2. 「正解に使う件」を「デモの想定ラベル」にする（人が確認した件が 20 件未満だと提案が出ないため）。
3. 「目標の誤り率」を 5% にする。
4. グラフで「自動で振り分ける割合」と「自動分の誤り率」を見る。
5. 表の「提案」と「いまの閾値」を比べる。
6. 反映するなら「選んだ閾値を反映」を押す。
7. 設定の「分類ごとの自動の閾値」に反映されたことを確かめる。戻すなら「共通の値に戻す」を押す。

**確かめること**
- 目標を厳しくすると、提案の閾値が上がり、自動の割合が下がる。

**分かること**
- 閾値を下げると自動が増えて人の手間が減るが、誤りも増える。
- 抜き取り確認は、誰も見ていない自動分の誤り率を補う。

---

## 9. 設定

**手順**
1. 「管理 → 設定」を開く。
2. 「個人情報のガードレール」を見る。
   - 接続先（Kev か MOCK）
   - 人の確認
   - 確率 0.3 と 0.5
   - 種類ごとの方針
   - ブロックした件の行き先
3. 「仕分け」を見る（自動 0.9・確認待ち 0.5・分類ごとの閾値）。
4. 「業務ルール」「Kev で先に判定」「抜き取り確認」「優先度の重み」を見る。
5. 触ったら「元に戻す」を押してから離れる。

**確かめること**
- 確認待ちの閾値を自動の閾値より大きくすると、保存できない。

**分かること**
- 方針は、マスク／ブロック／検出のみの 3 択（Bedrock Guardrails と同じ考え方）。
- 「Kev で先に判定」は、Jev の料金と外部への送信を減らす前段。
- 設定は、次に処理する件から効く。

## 10. 評価ダッシュボード

**手順**
1. 左ペインの「評価ダッシュボード」でアプリ一覧を見る。
2. 1 つ選び（例: 問い合わせ仕分け）、「ライブ評価」を開く。
3. ヘッダーを MOCK にし、件数を 5 にして「評価を開始」を押す。
4. 一致率、対応表、「不一致」の絞り込みを見る。
5. 「実行の種類」を「比較」にし、Kev と MOCK で実行する（Kev は並列 1）。
6. 「単発判定・履歴」で、自由入力の文面を判定する。

**確かめること**
- 比較の集計に「両方判定できた N 件のうち M 件が同じ」と出る。

**分かること**
- Jev と Kev の差を同じデータで数字として見られる。「Kev で先に判定」や閉域化を判断する根拠になる。
- 確信度の区分ごとの一致率で、確信度がどれだけ信用できるかを見られる。

## 11. 言い方チェック

**手順**
1. 「ツール → 言い方チェック」を開き、ヘッダーで接続先を選ぶ。
2. 例文「言い訳の入った謝罪」を押す。
3. 「判定する（Ctrl+Enter）」を押す（Kev では約 10 秒）。
4. 総合判定、目的、印象、観点のバー、文ごとの色を見る。
5. 「目的」を「報告・連絡」に変え、表示の変化を見る。
6. 「書き換え案を作る」を押す（sonnet、約 10 秒）。
7. 案を直してから「この案を判定する」を押し、比較表を見る。

**確かめること**
- 入力欄を変えると注意が出て、書き換えのボタンが押せなくなる。
- 案を編集すると、比較表に「編集前の案の比較」と出る。

**分かること**
- 判定は Jev/Kev が担い、書き換えは Claude が担う。
- 目的によって見る観点が変わる（報告では「期限が明確か」を問わない）。

## 困ったとき

| 症状 | 対処 |
|---|---|
| 5173 番の画面が開かない | 1. `ps -o stat,cmd -u $USER \| grep vite` で状態が `T` なら停止中<br>2. `dev.sh` を Ctrl+C で止める<br>3. `pkill -CONT -f node_modules/.bin/vite; pkill -f node_modules/.bin/vite` を実行する<br>4. `dev.sh` を起動し直す<br>急ぐときは 8000 番を開く |
| Kev が使えない・エラーになる | 1. `curl -s 127.0.0.1:8009/v1/models` で確かめる<br>2. 止まっていれば Kev を起動する<br>3. エラーの件は、受付箱の詳細の「再実行」で流し直す |
| Kev が遅い | CPU で動くため、1 回に数秒〜10 秒かかる |
| Jev が「上限」で止まる | 1. `JEVLAB_BUDGET_USD` で上限を変える（既定 $1.00）<br>2. サーバを起動し直す |
| 表示が古い | F5 で再読み込みする |
