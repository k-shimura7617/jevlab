# jevlab 伴走ガイド

起動済みの jevlab を自分で操作しながら、機能を 1 つずつ掴むための手順書です。

- 画面: http://127.0.0.1:5173（`scripts/dev.sh`）／ http://127.0.0.1:8000（ビルド版）
- 件は件名で指します。T 番号は「受付箱を空にする」と振り直されるので、あくまで例です。
- 分類が Jev のときは、1 件あたり約 $0.0001 かかります。右上の「Jev 利用額（目安）」で確かめられます。
- 実際の Slack とつなぐ手順は [slack-setup.md](slack-setup.md) にあります（つながなくても、この手順書はすべて疑似チャンネルで試せます）。

## 0. 準備と全体像

**手順**
1. http://127.0.0.1:5173 を開く。
2. 左ペインで、次の 3 つのまとまりを確かめる。
   - 運用ダッシュボード
   - 評価ダッシュボード
   - ツール
3. 運用ダッシュボードの「デモの進め方」を開き、6 ステップを眺める。
4. 受信シミュレータの「受付箱を空にする」を押し、OK を押す（設定と担当者は残る）。
5. 「最初から」を押す。

**確かめること**
- 流れ図の件数がすべて 0。
- シミュレータに「0 / 64 件」と出ている。

## 1. 受信と自動の流れ

**手順**
1. シミュレータの間隔を「2 秒ごと」にする。
2. 「1 件だけ受信」を 3 回押し、流れ図の動きを見る。
3. 左ペインの「受付箱」で 1 件をクリックする（完了した件は「完了を表示」で出る）。
4. 右の「経過（監査ログ）」を上から読む（受信 → 個人情報 → 分類 → 行き先）。
5. ダッシュボードで「▶ 受信を開始」を押し、流したら「⏸ 一時停止」を押す。
6. 間隔を「高速（並列 16）」にして「▶ 受信を開始」を押すと、0.1 秒ずつ受信し、16 件ずつ並べて処理する（進み具合と処理待ちの件数が出る）（Kev を使わない構成向け。Kev は 1 件ずつなので、ガードに Kev を使う設定では速くならない）。

**確かめること**
- どこに件がたまっているか。多いのは「個人情報の確認」。
- Kev を使う設定では、「ガードレール」に「Kev 待ち N 件・約 M 分（目安）」が出る（待ちがなければ出ない）。
- 右上の利用額の増え方。

**分かること**
- 個人情報のある件は、Jev に送る前に人の確認で止まる。
- 確信度が 0.9 以上なら自動で振り分け、0.5〜0.9 なら分類の確認、それ未満や緊急・強い不満ならエスカレーション。

## 2. 個人情報の確認（Kev）

| タグ | 意味 |
|---|---|
| 検出済み | 個人情報がすべて確定している（最初からチェック済み） |
| 未確定の候補 | 個人情報かどうかを自動では決めきれなかった候補がある（氏名に限らない） |
| 見落としの可能性 | ほかにも残っているかもしれない |
| 編集あり | 右側での編集が保存されている |

右側の下の「確認対象」に、個人情報として扱う種類が並ぶ（氏名・電話・メール・郵便番号・住所・カード・口座・生年月日・SNS アカウント）。

**① 開く**
1. 左ペインの「個人情報の確認（Kev）」を開く。
2. 帯に「N / M 件を選択」と出ていることを確かめる。

**② 氏名を決める（件名「返金がされていません」）**
1. その件をクリックする。
2. 表の「松本 恵」の「個人情報」にチェックを入れる。
3. 帯に「編集を保存しました」と出ることを確かめる。
4. プレビューが【氏名】になっていることを確かめる。
5. ボタンが「マスクして仕分け（1 箇所）」になっていることを確かめる。
6. 別の件を開いてから戻り、チェックが残っていることを確かめる。
7. 一覧に「編集あり」のタグが付いていることを確かめる。
8. 右のボタンで処理するか、左のチェックを入れておいて ⑤ でまとめて処理する。
9. 元に戻したいときは、帯の「編集を取り消す」を押す。

**③ 見落としを読む（件名「こんにちは、ひだまり手づくり市の…」）**
1. その件を開き、本文を読む。
2. 個人情報がなければ「そのまま仕分け」を押す。
3. あれば、該当箇所を選択 → 種類を選ぶ →「個人情報として追加」→「マスクして仕分け」の順に押す。

**④ ブロック（件名「二重に引き落とされています」）**
1. その件を開く。
2. ボタンが「ブロック（Jev に送らない）」だけになっていることを確かめる。
3. 押すと、Jev を通さずにエスカレーションへ回る。口座番号の件（件名「ブランケットの品質について」）も同じ。

**⑤ まとめて処理**
1. 帯のボタンを押す。
   - 通常は「選んだ N 件をマスクして仕分け」。
   - ブロック対象を含むときは「選んだ N 件を処理（マスクして仕分け M・ブロック K）」。
2. 完了メッセージの件数を確かめる。

**⑥ 行き先を見る**
1. ダッシュボードの流れ図で、「個人情報の確認」が減ったことを確かめる。

**分かること**
- 電話・メール・カードなど、形で決まる種類は規則で確定する。氏名だけを Kev に聞く。
- 規則で確定した種類は、チェックを外しても処理のときにサーバが元に戻す。
- 編集していない件をまとめて処理すると、候補をすべてマスクする（安全側）。編集した件は、その内容で処理する。
- Jev に届くのは、プレビューの伏せ字の本文だけ。

## 3. 分類の確認（Jev）

**手順**
1. 左ペインの「分類の確認（Jev）」を開く。
2. 「確認待ち」タブで 1 件を選び、右の分類の確率を見る。
3. キーで確定する。
   - `1`〜`4`: 問い合わせ／クレーム／お礼／その他
   - `j` / `k`: 次の件・前の件
4. 「分類で絞り込む」のチップを押してみる。
5. 「並び順」を「優先度」と「受信順」で切り替える。
6. 「優先度の重み」を開き、「緊急」を最大にして並びの変化を見る（見たら戻す）。
7. 「抜き取り確認」タブで 1 件を確かめる。

**確かめること**
- 確定した件が一覧から消え、チャンネルに投稿される。
- 重みを変えると、判定し直さずに並び順だけが変わる。

**分かること**
- 人の確定と抜き取りの結果が、閾値の調整（項目 8）の正解になる。
- 重みは並び順だけを変え、Jev への問い合わせはしない。

## 4. エスカレーション

**手順**
1. 左ペインの「エスカレーション」を開く。
2. 各行の表示を見る。
   - 「⏱ 残り N 時間（営業時間）」または「⏱ 残り N 分（営業時間）」
   - 担当者、または「推定: ◯◯」
   - 「自動」の印
3. 1 件を選び、「担当の推定」の「この担当にする」を押す。
4. メモを書いて「追加」を押す。
5. 「最終の分類」を選び、「対応完了にする」を押す。
6. 帯の担当者の欄で 1 人を選ぶ。
   - その人の担当の件にチェックが入り、上に並ぶ。
   - 次に、推定がその人の未割り当ての件が「推定」の印つきで並ぶ。
7. チェックを足したり外したりして、「◯◯の担当を更新（追加 N・外す M）」を押す。
8. 担当者を選ばずにチェックだけ付けると、「選んだ N 件を割り当てる」になる。

**確かめること**
- 完了は、エスカレーションの投稿のスレッドへの返信と ✅ で知らせる（分類のチャンネルには投稿しない）。
- チェックを外した件は、その人の担当から外れる。

**分かること**
- 担当の推定は分類と同じ 1 回の問い合わせで行うので、追加料金はほぼない。
- 推定した担当の確率が 0.7 以上なら自動で割り当てる。届かないときも、確率が一番高い人に仮で割り当てる（担当が 1 人ならその人）。一覧では「仮」と出る。
- カード番号などでブロックした件は「個人情報のため Jev 未送信」と出る。
- 対応目安は営業時間で数える（既定は 9 営業時間＝平日 9:00〜18:00 の 1 営業日）。昼休み・夜間・休日は進まない。
- 個人情報のためブロックした件には、Kev（ローカル）による参考の分類と担当の推定が付く。自動では振り分けない。
- 人が決めて完了した件は、次からの推定の「例」になる。

## 5. チャンネル（疑似 Slack）

**手順**
1. 左ペインの「チャンネル」を開く。
2. #cs-問い合わせ／#cs-クレーム／#cs-お礼／#cs-その他／#cs-エスカレーション を順に開く。
3. 投稿の件名（伏せ字）、注文番号、投稿者を見る。
4. 「#お問い合わせ窓口」に 1 行書いて「送信」する。
5. ダッシュボードで、その書き込みが受付箱に届いたことを確かめる。

**確かめること**
- 投稿に差出人の名前が載っていない。

**分かること**
- 外に出る見出しは、個人情報の候補をすべて伏せている。
- 実際の Slack にも流せる（コネクタ画面で設定する。手順は [slack-setup.md](slack-setup.md)）。流すのは伏せた見出しだけで、#お問い合わせ窓口（元の本文）は流さない。
- Slack の投稿には件の詳細へのリンク（画面で開く）が付く。完了すると、その投稿のスレッドに返信が付き、投稿に ✅ が付く。
- Slack の「画面で開く」は、エスカレーションの投稿ならエスカレーションの画面（もう完了していれば受付箱）、それ以外は受付箱でその件を開く。
- エスカレーションと、返信の要る分類で振り分けた件は、スレッドで担当者（未定なら振り分け担当）をメンションする。文面はメンション・「対応お願いします。」・「担当確信度 0.42」を 1 行ずつ（未定なら「担当を決めてください。」と推定）。担当未定のまま対応目安の 60 分前になると、振り分け担当に 1 回だけ知らせる。

## 5.1 振り分けた件を完了にする

**手順**
1. 受付箱で「振り分け済み」の件を開く（Slack の投稿の「画面で開く」からでもよい）。
2. 「最終の分類」が、いまの分類になっていることを確かめる。
3. 分類が合っていれば、そのまま「対応完了にする」を押す。違っていれば、正しい分類に切り替えてから押す。

**確かめること**
- 完了すると状態が「完了」になり、経過に「対応完了」が残る。

**分かること**
- 触らずに完了した件は「分類は合っていた」、切り替えた件は「修正した」として、閾値の調整（項目 8）の正解に数える。抜き取り確認を待っている件なら、その結果にもなる。
- タスクの状態・担当・完了は jevlab が正本で、Slack は知らせる場所。

## 6. 担当者

**手順**
1. 左ペインの「管理 → 担当者」を開く。
2. 「担当範囲（Jev が読む説明）」を読む。
3. 「＋ 担当者を追加」で 1 人足し、名前を入れる（カーソルが外れると自動で保存される）。
4. 「自動の割り当て」の設定を見る（オン・オフ、自動で割り当てる確率 0.70、例を渡すか）。
5. 「推定の当たり具合」を見る（項目 4 で完了した件があれば出る）。
6. 追加した担当者を削除する（確認が出る）。
7. 「担当」のチェックを外すと、一覧に残したまま推定・割り当て・振り分け担当（当番）から外れる。

**確かめること**
- 右上に「保存しました」と出る。次にエスカレーションになる件から反映される。
- 完了件が 10 件未満のときは「参考値」と出る。

**分かること**
- 担当範囲を重ならないように書くと、推定が当たりやすい。
- 「取り違えが多い組み合わせ」は、担当範囲を直す手がかりになる。

## 7. 手で 1 件送る・ファイルで取り込む

**手で送る**
1. 「受付箱」右上の「お客様としてメールを送る」を押す。
2. 本文を入れて「送信」する（例: 「電話は 090-0000-1234 です」）。
3. 一覧で行き先を確かめる。個人情報があれば「個人情報の確認」へ進む。

**ファイルで取り込む**
1. 「管理 → コネクタ」の「ファイル取り込み」を開く。
2. 読めるファイル: CSV（UTF-8・Shift_JIS）、Excel（.xlsx）、メール（.eml・.mbox）、Slack のエクスポート（.zip）。
   - Outlook のメールは .eml で保存する（.msg・.pst は読めない）。Gmail は Takeout の .mbox。
3. 「サンプル CSV」を押し、ダウンロードしたファイルをドロップ欄に入れる。
4. 列の対応と「過去の分類の対応」、先頭 5 件を確かめる。
5. 「N 件を取り込む」を押し、「取り込みますか？」で OK を押す。ダッシュボードの「処理フロー」に移り、進み具合のバー（「N / 全 M 件 処理済み」）が伸びていく（完了済みとして取り込んだ件は、運用の集計に入れないので処理フローには出ない）。

**見本のファイル**（`docs/samples/import/`。すべて架空のデータ）

| ファイル | 確かめること |
|---|---|
| `過去の問い合わせ_ShiftJIS.csv` | Shift_JIS が文字化けしない。「種別」（問合せ・苦情・お礼・その他）が分類に当たる。本文だけの行も読める |
| `過去の問い合わせ_UTF8BOM.csv` | 同じ内容の UTF-8（BOM 付き） |
| `問い合わせ管理表.xlsx` | Excel の読み込み。受信日時は Excel の日付（シリアル値）で入っている |
| `問い合わせ_1通.eml` | メール 1 通（Outlook の Web で保存した形） |
| `Gmail_Takeout.mbox` | 3 通。HTML だけのメールと、古い形（ISO-2022-JP）のメールを含む |
| `Slackエクスポート.zip` | 取り込むのは 2 件。スレッドの返信・参加の通知・ボットの投稿は除く |
| `読めない例.xls` | 読めない形式のときの案内（.xlsx か CSV で保存） |
| `大量_100件.csv`・`大量_500件.csv`・`大量_1000件.csv` | Jev の並列処理の速さと振り分け。用件・添える文・あいさつをランダムに組み合わせた、すべて違う内容。UTF-8（BOM 付き）、種別あり、個人情報なし（`scripts/make_bulk_samples.py` で作り直せる） |

**大量の件で Jev の速さを見る**
1. 「運用 → 設定」で、ガードの「Kev で判定する」をオフにし、「人の確認」もオフにする（Kev は 1 件ずつなので、オンだとそこで詰まる）。
2. ダッシュボードの受信シミュレータの間隔を「高速（並列 16）」にする（取り込んだ件も 16 件ずつ処理する）。
3. `大量_1000件.csv` を取り込み、処理フローの「処理待ち」が減っていく速さを見る。
   - MOCK では 1000 件が約 18 秒で終わった（テスト用サーバで測定）。
   - Jev の利用額は、デモの実績（64 件で約 $0.0018）から、1000 件で約 $0.03 の見込み。
   - 見終わったら、受信シミュレータの「受付箱を空にする」で消す。

**過去の問い合わせで試算する**
1. 過去の分類の列を対応付け、「完了済みの問い合わせとして取り込む」にチェックを入れる（既定はオフ）。
2. 取り込んだ件は仕分けまで行い、投稿・人の対応には回さずに完了にする（個人情報の候補はすべて伏せる。受付箱では「完了を表示」で見える）。
3. 「閾値の調整」で「想定ラベル・過去の分類」を選ぶと、閾値ごとの自動化率と誤り率が出る。

**メールで返信する**
- 差出人のアドレスがある件は、件の詳細の「メールで返信」で、宛先と「Re: 件名」を入れたメールソフトが開く（jevlab はメールを送らない）。

**確かめること**
- コネクタを「切断」すると、その経路から受け付けなくなる。確かめたら「接続する」で戻す。
- 「Slack」の欄に、送信・受信の状態が出る。トークンを入れていなければ「未設定」。

**分かること**
- どの経路から来ても、同じ流れ（ガード → 仕分け → 振り分け）を通る。

## 8. 閾値の調整

**手順**
1. 「管理 → 閾値の調整」を開く。
2. 「正解に使う件」を「想定ラベル・過去の分類」にする（人が確認した件が 20 件未満だと提案が出ないため）。
3. 「目標の誤り率」を 5% にする。
4. グラフで「自動で振り分ける割合」と「自動分の誤り率」を見る。
5. カードごとに「提案」と「いまの閾値」を比べる。
6. 提案のあるカードで「0.90 → 0.64 に変更」のボタンを押す（押すとその場で反映される）。
   - 「全体」のカードは、共通の自動の閾値を変える。
   - いまの値が提案と同じなら「提案どおり」と出る。
   - 件数が 20 件に満たない分類には、提案が出ない。
7. 設定の「分類ごとの自動の閾値」に反映されたことを確かめる。戻すなら「共通の値に戻す」を押す。

**個人情報の判定（Kev）の当たり具合を見る**
1. 「個人情報の判定（Kev）」の 2 つの表を見る（行: モデル、列: 人）。
   - 候補（氏名など）: 候補ごとに、モデルの判定と人の判断を比べる。
   - 候補外の残り: 閾値以上で疑ったかと、人が候補外の箇所を足したかを比べる。
2. 数えるのは、個人情報の確認で人が見て処理した件だけ（一括で編集せずに流した件は除く）。

**検知漏れ（ガードの見逃し）を報告する**
1. 受付箱で、仕分け済みの件（振り分け・確認待ち・エスカレーション・完了）を開く。
2. 「検知漏れを報告」を開き、本文で見逃した箇所を選択する。
3. 種類を選んで「報告」を押す。
4. 閾値の調整の「検知漏れ」で、報告の件数と「取りこぼしを疑う確率」の目安を見る。

**確かめること**
- 目標を厳しくすると、提案の閾値が上がり、自動の割合が下がる。
- 検知漏れの目安は、見逃しを何割拾うかと、その分増える確認の件数の組で出る。

**分かること**
- 閾値を下げると自動が増えて人の手間が減るが、誤りも増える。
- 抜き取り確認は、誰も見ていない自動分の誤り率を補う。

## 9. 設定

**手順**
1. 「管理 → 設定」を開く。
2. 「個人情報のガードレール」を見る。
   - 有効にする（オフにすると元の本文のまま Jev に送る。デモ用）
   - 「Kev で判定する」（オフで規則だけ。Kev を使わないので速い。左ペインは「個人情報の確認（規則のみ）」になる）
   - 接続先（Kev か MOCK）
   - 人の確認
   - 確率 0.3 と 0.5
   - 種類ごとの方針
   - ブロックした件の行き先
3. 「仕分け」を見る（自動 0.9・確認待ち 0.5・分類ごとの閾値）。
   - 「分類とチャンネル」で「＋ 分類を追加」を押し、表示名・説明・チャンネル（例: 配送／配送の遅れ・破損／#cs-配送）を入れる。カーソルを外すと保存され、ダッシュボードとシミュレータの分類に出る。
   - 試したら「削除」で消す（使った分類は削除できないので「使う」を外す）。
   - 「返信不要」（既定はお礼）の分類は、自動で振り分けた件・分類の確認で確定した件とも、投稿し、スレッドに完了を書いて ✅ を付けて完了にする（担当の割り当て・メンションはしない）。
   - 「返信の要否を判定」（既定はその他）の分類は、件ごとに Jev が返信の要否を判定する。仕入れの提案など返信の要る件は担当をメンションし、宣伝など要らない件は返信不要と同じく完了にする。
4. 「業務ルール」（強い不満とみなす確率 0.35・僅差とみなす差 0.1）「Kev で先に判定」「抜き取り確認」「優先度の重み」を見る。
5. 「対応目安」を見る（9 営業時間・平日・9:00〜18:00）。
6. Slack の呼び出し（振り分け担当・担当未定の知らせ）は「管理 → コネクタ」の Slack の欄にある。
7. 変更は自動で保存される（文字の欄とスライダーはカーソルが外れたとき、チェック・選択は変えたとき）。触ったら元の値に戻してから離れる。

**確かめること**
- 確認待ちの閾値を自動の閾値より大きくすると、保存できない。そのまま離れようとすると、変更を破棄してよいかを聞かれる。
- ガードレールを外すとき・種類を「検出のみ」にするときだけ、確認が出る。

**分かること**
- 方針は、マスク／ブロック／検出のみの 3 択（Bedrock Guardrails と同じ考え方）。
- 「Kev で先に判定」は、Jev の料金と外部への送信を減らす前段。
- 「モデルで判定する」をオフにすると、氏名などの候補はすべて個人情報として扱う（見逃さない代わりに、伏せすぎることがある）。
- 自動の閾値を超えても、分類の上位 2 つが僅差のときは人の確認に回る。
- 設定は、次に処理する件から効く。

## 10. 評価ダッシュボード

**確かめること**

**分かること**

- 確信度の区分ごとの一致率で、確信度がどれだけ信用できるかを見られる。

## 11. 言い方チェック

**手順**
1. 「ツール → 言い方チェック」を開き、ヘッダーで接続先を選ぶ。
   - 相手（上司・同僚・部下・取引先・お客様・友人・家族）と場面は、既定で「指定なし」（一般的なビジネスの相手・場面として判定）。
2. 例文「言い訳の入った謝罪」を押す。
3. 「判定する」を押す（Ctrl+Enter でもよい）（Kev では約 10 秒）。
4. 総合判定、目的、印象、観点のバー、「きつく見える文」（濃いほどきつく見える）を見る。
5. 「目的」を「報告・連絡」に変え、表示の変化を見る。
6. モデル（sonnet がおすすめ、opus は微妙なニュアンス向き）を選び、「書き換え案を作る」を押す（sonnet で約 10 秒）。
7. 案を直してから「この案を判定する」を押し、比較表を見る。

**確かめること**
- 入力欄を変えると注意が出て、書き換えのボタンが押せなくなる。
- 案を編集すると、比較表に「編集前の案の比較」と出る。

**分かること**
- 判定は Jev/Kev が担い、書き換えは Claude が担う。
- 目的によって見る観点が変わる（報告では「期限が明確か」を問わない）。

## 12. 契約・規約チェック

**分かること**

- 判定は Jev/Kev、説明は Claude（言い方チェックと同じ分担）。

## 13. 返信前チェック

**手順**
1. 「ツール → 返信前チェック」を開き、「例」を押して「判定する」を押す。
2. 総合判定と、観点（質問に答えている・方針を超えた約束・きつい・素っ気ない・謝罪）、足りない情報を見る。
3. 枠の下の「方針」を押すと、モーダルで判定と AI返信案に使う方針を直せる（Esc か「閉じる」で閉じる。「？」に説明）。
4. 「AI返信案の作成」（Claude・sonnet）で案を作る。案は書いた分から順に出る（ストリーミング）。下書きがあれば判定の指摘をもとに直した案、なければ問い合わせから書いた案になる。「採用」で下書きに入れ、「この案を判定する」で下書きと比べる。
5. 運用の件の詳細（受付箱・分類の確認・エスカレーション）の「返信内容の検討」ボタンから開くと、その件の問い合わせ（個人情報を伏せたもの）が入る。
   - 差出人のアドレスがある件は、判定した後に結果の枠の「この内容で返信」（「判定する」と同じ高さ）を押すと、宛先・「Re: 件名」・判定した下書きを入れたメールソフトが新しいタブで開く（判定の後に下書きを書き換えたら、判定し直すまで押せない）。

**分かること**
- 問い合わせにも下書きにも、個人情報の候補を伏せてから Jev・Claude に送る。
- 足りない情報は、候補（注文番号・連絡する時期・お客様にお願いすることなど）ごとに「必要なのに書かれていないか」を聞く。
- 確認中の件では、返品・交換の期限や手順は「足りない」とせず、AI の案にも書かない（確認のあとに案内すると書く）。書いてよい期日は、こちらから連絡する時期だけ。
