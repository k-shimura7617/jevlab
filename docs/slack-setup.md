# 実際の Slack とつなぐ手順

jevlab は 127.0.0.1 でだけ待ち受けているため、Slack から呼び出せる公開 URL がありません。
そこで **Socket Mode**（アプリから Slack に WebSocket でつなぎに行く方式）を使います。
ngrok などで外に公開する必要はありません。

できること:

| 方向 | 内容 | 必要なトークン |
|---|---|---|
| 送信 | 振り分け・エスカレーション・対応完了の投稿を、指定した Slack チャンネルにも流す。投稿には件の詳細へのリンクを付け、完了したらスレッドに返信して ✅ を付ける | `SLACK_BOT_TOKEN`（xoxb-） |
| 受信 | 指定した Slack チャンネルに人が書いたメッセージを、受付箱に取り込む | `SLACK_BOT_TOKEN` と `SLACK_APP_TOKEN`（xapp-） |

流すのは、個人情報を伏せた見出し（例: `T-0012「箱が潰れていました」`）と抽出した項目だけです。
お問い合わせ窓口（元の本文）は流しません。

## 1. Slack アプリを作る（マニフェストから）

1. https://api.slack.com/apps を開き、「Create New App」→「From a manifest」を選ぶ。
2. 使うワークスペースを選ぶ。
3. 次の YAML を貼り付けて作成する。

```yaml
display_information:
  name: jevlab
  description: 問い合わせの仕分け（検証用）
features:
  bot_user:
    display_name: jevlab
    always_online: false
oauth_config:
  scopes:
    bot:
      - chat:write          # 投稿する
      - reactions:write     # 対応完了の ✅ を付ける
      - channels:history    # 公開チャンネルのメッセージを受け取る
      - channels:read       # チャンネルの情報を読む
settings:
  event_subscriptions:
    bot_events:
      - message.channels    # 公開チャンネルのメッセージ
  interactivity:
    is_enabled: false
  org_deploy_enabled: false
  socket_mode_enabled: true
  token_rotation_enabled: false
```

非公開チャンネルも使う場合は、`groups:history`・`groups:read` と `message.groups` を足してください。

作成済みのアプリに権限を足すときは、作り直す必要はありません。「OAuth & Permissions」→「Bot Token Scopes」でスコープを追加し、画面上の案内から再インストールします。

## 2. トークンを取る

1. **App-Level Token（xapp-）**
   - 「Basic Information」→「App-Level Tokens」→「Generate Token and Scopes」を開く。
   - スコープに `connections:write` を付けて作る。
   - 表示された `xapp-…` が `SLACK_APP_TOKEN` です。
2. **Bot Token（xoxb-）**
   - 「Install App」→「Install to Workspace」でインストールする。
   - 表示された `xoxb-…` が `SLACK_BOT_TOKEN` です。

## 3. チャンネルを用意して、ボットを招待する

1. 投稿先・受信用のチャンネルを作る（既存のものでも可）。例:
   - 投稿先: `#jevlab-エスカレーション`
   - 受信用: `#jevlab-お問い合わせ`
2. 各チャンネルで `/invite @jevlab` を実行する。
   - 招待していないチャンネルには投稿できません（`not_in_channel` になります）。
3. チャンネル ID を控える。
   - チャンネル名をクリック →「チャンネル詳細」の一番下にある `C` で始まる ID です。

## 4. .env にトークンを入れる

リポジトリ直下の `.env` に次の 2 行を足します（値は自分のトークン）。

```
SLACK_BOT_TOKEN=xoxb-...
SLACK_APP_TOKEN=xapp-...
```

- `.env` は Git に入れないでください。
- トークンはサーバの中だけで使い、画面や API には出しません。

## 5. サーバを起動し直す

トークンは起動時に読み込みます。`scripts/dev.sh` を Ctrl+C で止めて、起動し直してください。

## 6. 画面で設定する（運用 → 管理 → コネクタ →「Slack」）

1. 「送信」「受信」の状態が「未設定」でなくなっていることを確かめます。
2. **投稿先のチャンネル ID** に、流したい疑似チャンネルごとの Slack のチャンネル ID を入れます。
   - 空欄のチャンネルは流しません。
   - まずは `#cs-エスカレーション` だけ入れるのがおすすめです。
3. 「振り分け・エスカレーションの投稿を Slack にも流す」にチェックを入れます。
4. **受信するチャンネル ID** に、受信用チャンネルの ID を入れます。
5. 「下のチャンネルの書き込みを受付箱に取り込む」にチェックを入れます。すぐに接続します。

変更は自動で保存します（文字の欄はカーソルが外れたとき、チェックは変えたとき）。

## 7. エスカレーションの呼び出しを設定する（任意）

エスカレーションの投稿は「親の投稿（画面へのリンクつき）」と「スレッドの返信」に分かれます。

| 状況 | スレッドで呼び出す人 |
|---|---|
| 確率が高く、自動で担当を割り当てた | その担当者 |
| 確率が閾値に届かず、仮で割り当てた | その担当者（「仮で割り当て」と書く） |
| 担当が未定（担当中の人がいない・自動の割り当てがオフ） | 振り分け担当（当番）。推定した担当は名前だけ書く |
| 人が担当を変えた・外した | 新しい担当者（外したときは呼び出さない） |
| 対応を完了した | 呼び出さない（完了と書くだけ） |
| 担当が未定のまま、対応目安の N 分前（営業時間）になった | 振り分け担当を **1 回だけ**。同じ件で繰り返さない |

1. **担当者の Slack ID を登録する。**
   - Slack でその人のプロフィールを開き、「︙」→「メンバー ID をコピー」で `U…` を控える。
   - 運用 → 担当者 の「Slack ID」欄に入れる（カーソルが外れると保存される）。
   - 空欄の人は、メンションせず名前だけ書きます。
2. **振り分け担当（当番）を選ぶ。** コネクタ画面の「振り分け担当（当番）」で選ぶ。
3. **担当未定の知らせ**
   - オン・オフと「何分前か」を変えられます（既定は 60 分前・オン）。
   - 対応目安は、運用 → 設定 の「対応目安」で決めます（既定は平日 9:00〜18:00 の 9 営業時間＝1 営業日）。
   - 対応目安も「何分前か」も営業時間で数えます。昼休み・夜間・休日は進みません。
   - 知らせすぎないよう、1 件につき 1 回だけです。
4. **画面へのリンク**
   - 既定は `http://127.0.0.1:5173`（dev.sh の画面）です。
   - ビルド版で使うなら `http://127.0.0.1:8000` にします。
   - リンクは自分の PC でしか開けません（127.0.0.1 のため）。

## 8. 動作を確かめる

- **送信:** 受信シミュレータで 1 件流します。Slack の投稿先に見出しが届けば成功です。コネクタ画面の「送信」の件数が増えます。
  - エスカレーションの完了は、エスカレーションの投稿のスレッドだけで知らせます（分類のチャンネルには投稿しません。[ADR-0024](adr/0024-escalation-close-notice-in-thread-only.md)）。
- **完了:** 投稿の「画面で開く」から件の詳細を開き、「対応完了にする」を押します。元の投稿のスレッドに「対応完了」と返信され、投稿に ✅ が付けば成功です。
  - 最終の分類を切り替えて完了すると、返信に「分類を ◯ から ◯ に修正」と書き足します。
- **受信:** 受信用チャンネルに「注文した箱が潰れていました」などと書き込みます。受付箱に経路「Slack」の件が届けば成功です。
  - 取り込むのは次のメッセージだけです。
    - スレッドの返信は取り込みません。
    - 編集・削除・ボットの投稿も取り込みません。

## うまくいかないとき

| 表示 | 原因と対処 |
|---|---|
| 「未設定」のまま | `.env` にトークンがない、またはサーバを起動し直していない |
| 送信: `not_in_channel` | そのチャンネルにボットを招待していない（`/invite @jevlab`） |
| 送信: `channel_not_found` | チャンネル ID の誤り |
| 送信: `invalid_auth` | Bot Token の誤り・失効 |
| 送信: リアクションに失敗: `missing_scope` | Bot Token Scopes に `reactions:write` がない。追加して再インストールする（返信は届き、✅ だけ付かない） |
| 受信がエラー | App-Level Token に `connections:write` がない、または Socket Mode が無効 |
| 受信: 件が届かない | 受信するチャンネル ID の誤り、ボット未招待、`message.channels` の購読がない |

- 一時的な失敗（混み合い・429）は、待ってから同じ投稿を送り直します。
- 設定の誤りによる失敗は、その投稿を飛ばして次へ進みます。エラーはコネクタ画面に出ます。
