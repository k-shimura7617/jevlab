# 0006. 優先度は観点ごとに判定し、重み付けはコードと画面で行う

- 状態: 採用
- 日付: 2026-09-26
- 関連: [architecture.md §3](../architecture.md#3-1-件の流れ)

## 背景と課題

対応の順番を決める「優先度」が欲しい。
「優先度は？」と 1 問で聞くと、何を重く見るかを後から変えられない。

## 検討した選択肢

1. 優先度を 1 問の Score で聞く
2. **観点（不満度・緊急・返金要求・公にする可能性）を別々に判定し、重み付き平均をコードで計算する**

## 決定

選択肢 2 を採用する。

- 観点ごとの値は 0〜1 に正規化し、重み（設定・画面のスライダー）で平均する。
- サーバと画面で同じ式を使う。
- 重みを変えても判定し直さない（再課金なし）。
- 並び順の変更にだけ使い、振り分けの判断は別のルールで行う（強い不満・緊急なら人へ）。

## 結果

- 良い点
  - 重みの意味が明確で、利用者が画面で調整できる。
  - 観点の値は、後で集計や機械学習の特徴量にも使える。
- 悪い点
  - 「重大な観点が 1 つでもあれば最優先」のような条件は、重み付き平均では表せない。こうした条件は、別のルールとして持つ。
