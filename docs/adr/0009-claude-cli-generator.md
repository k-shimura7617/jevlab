# 0009. 文章の生成は、生成器の型の裏で claude -p（サブスク枠）を使う

- 状態: 採用
- 日付: 2026-09-26
- 関連: [0001](0001-jev-for-judgment-claude-for-generation.md)

## 背景と課題

言い方チェックの書き換え案には、文章を生成するモデルが必要になる。
検証段階では、API の従量課金ではなく、既存の Claude のサブスク枠を使いたい。将来は API キーに差し替えられるようにしておきたい。

## 決定

- 生成器を型（`Generator` Protocol）で定義する。いまの実装は `ClaudeCliGenerator` だけで、`claude -p` を子プロセスで呼ぶ。
  - オプション: `--output-format json`、`--json-schema`、ツール・MCP・スラッシュコマンド・設定の読み込みはすべて無効。
- 実装は環境変数 `JEVLAB_GENERATOR` で選ぶ。API 版を足すときは、ここに追加する。
- 子プロセスの起動条件
  - プロンプトは標準入力で渡す。
  - 推測できない名前の、空の一時ディレクトリで起動する（プロジェクトの CLAUDE.md を読ませないため）。
  - タイムアウトやキャンセルのときは子プロセスを止める。
- 子プロセスに渡さない環境変数: `TYPESAFE_*`、`KEV_*`、`ANTHROPIC_API_KEY`。サブスク枠で動かし、jevlab の鍵を渡さないため。
  - `JEVLAB_CLAUDE_USE_API_KEY=1` のときだけ API キーを渡す。
- 同時に走らせるのは 2 本まで（サブスク枠を守るため）。

モデルは、6 文面 × 3 モデルで比べた結果、既定を sonnet にした。

| モデル | 時間の中央値 | 位置づけ |
| --- | --- | --- |
| sonnet | 7.2 秒 | 既定（速さと質のつり合い） |
| opus | 8.5 秒 | 微妙なニュアンスの直しがやや上 |
| haiku | 32.3 秒 | 遅く、出力も長い。選択肢から外した（2026-09-26） |

## 結果

- 良い点
  - 検証中の追加料金がかからない。
  - API 版への差し替えが 1 か所で済む。
- 悪い点
  - 手元に Claude Code がログイン済みで入っている必要がある（サーバ用途には向かない）。
  - 応答の時間がばらつく。
