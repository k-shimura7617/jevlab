# 0010. 個人情報の確認の編集は、サーバ側に下書きとして保存する

- 状態: 採用
- 日付: 2026-09-26
- 関連: [0002](0002-kev-pii-guardrail.md)、[0007](0007-human-in-the-loop-queues.md)

## 背景と課題

個人情報の確認画面では、人が「個人情報」のチェックを入れたり、漏れていた箇所を追加したりする。
以前は、この編集を画面の中だけで持っていたため、次の問題があった。

1. 別の画面に移ると編集が消えた（利用者から指摘）。
2. 左のチェックでまとめて処理すると、編集は使われず、サーバ側の検出内容で処理された（レビューで指摘）。

## 検討した選択肢

1. ブラウザ（sessionStorage）に保存する。まとめて処理の要求に、編集した範囲を含めて送る
2. **サーバの件に「下書き」（`pii_draft`）として保存する。まとめて処理はそれを使う**

## 決定

選択肢 2 を採用する。

- **保存:** 操作のたびに `PUT /api/ops/items/{id}/pii/draft` で保存する。検出した内容と同じに戻したら下書きを消す。
  - 保存は 1 本の列にして順番を守る。
  - まとめて処理は、保存の完了を待ってから始める。
- **まとめて処理:** 下書きがある件は、その判断どおりに処理する。
  - 下書きがない件は、本文を見ていないので、未確定の候補もマスクする（安全側）。
- **確定したら** 下書きは消す。確認待ち以外の件には保存できない。
- **画面の表示:** 「編集を保存しました」の帯と「編集を取り消す」を出す。一覧には「編集あり」のタグを付ける。

## 結果

- 良い点
  - 画面を移っても、再読み込みしても編集が残る。
  - 1 件ずつの処理と、まとめて処理の結果が一致する。
- 悪い点
  - 操作のたびに書き込みが発生する（クリック程度の頻度なので問題にならない）。
