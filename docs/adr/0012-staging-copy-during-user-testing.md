# 0012. 利用者の動作確認中は、別のコピーで実装して区切りで反映する

- 状態: 採用
- 日付: 2026-09-26
- 関連: [handoff.md](../handoff.md)

## 背景と課題

利用者は、自分の環境のサーバ（`scripts/dev.sh`。API は自動で再読み込み、画面は HMR）で動作確認をしている。
同じリポジトリを直接変更すると、確認の途中で次のことが起きる。

- サーバが再起動したり、画面が差し替わったりする。
- 依存関係が変わると、`uv sync` が必要になり、アプリが止まる。

リポジトリは、まだ git で管理していない。

## 検討した選択肢

1. 同じリポジトリを直接変更する（確認中に壊れうる）
2. git のブランチ / worktree で分ける（git が必要）
3. **リポジトリのコピー（ステージング）で実装し、別のポートで確かめる。区切りで差分を示し、利用者の了承を得て元のリポジトリへ反映する**

## 決定

選択肢 3 を採用する。git を導入したら、選択肢 2 に移る。

- 作業用のコピーと、変更前の基準のコピーは、それぞれ別の場所に置く（`.env` と `var/` はコピーしない）。
- 確かめるときは別のポートを使う（API 8010、画面 5174）。利用者のポート（8000 / 5173）と Kev（8009）には触れない。
- 反映の前に、次の 3 点を利用者に伝えて了承を得る。
  - 変更したファイル
  - 再起動・再読み込みが必要か
  - 依存関係が増えるか
- ドキュメント（`docs/`）は、動いているサーバが監視していないので、元のリポジトリに直接書いてよい。

## 結果

- 良い点
  - 利用者の確認を止めずに、並行して実装・テストできる。
  - 反映が 1 回にまとまるので、影響の範囲を事前に説明できる。
- 悪い点
  - コピーと元のリポジトリの差分を管理する手間がある。git の導入が望ましい。
