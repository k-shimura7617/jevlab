# 0011. 画面は同じリポジトリの Vite ビルドを FastAPI から配信する

- 状態: 採用
- 日付: 2026-09-26
- 関連: [architecture.md §2.6](../architecture.md#26-画面--frontendsrc)

## 背景と課題

画面と API を別々に配置すると、オリジンの違い（CORS）や、配置の手間が増える。
一方で、開発中は画面の即時反映（HMR）が欲しい。

## 決定

- 画面は `frontend/`（Vite + React + TypeScript）に置き、ビルドの出力を `src/jevlab/static/` に書き出す。
  - FastAPI は `/static` と、画面のパスへの `index.html` を返す（同じオリジン・同じポート）。
- 起動のスクリプト
  - `scripts/start.sh`: 毎回ビルドしてから起動する（ビルド版）。
  - `scripts/dev.sh`: API（自動再読み込み）と Vite の開発サーバ（HMR、5173 番）を同時に動かし、`/api` を中継する。
  - 注意: Vite は、裏で動かすと端末の入力を読もうとして止まってしまう。そのため入力を `/dev/null` にしている（2026-09-26 に修正）。

## 結果

- 良い点
  - 1 つのサーバ・1 つのポートで配信できる。API キーをブラウザに渡さない構成と相性が良い。
- 悪い点
  - ビルド版で確かめるには、ビルドのし直しが必要になる。
