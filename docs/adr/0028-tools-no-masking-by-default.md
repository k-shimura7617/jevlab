# 0028. ツールは既定で伏せない。ローカルの個人情報チェックを任意で使う

- 状態: 採用
- 日付: 2026-09-27
- 関連: [ADR-0002](0002-kev-pii-guardrail.md)、[ADR-0021](0021-sns-accounts-as-pii.md)

## 背景と課題

- 運用ダッシュボードは、一般のお客様からの問い合わせを受ける。個人情報は Kev と規則で伏せてから Jev に送る。
- ツール（言い方チェック・返信前チェック・契約・規約チェック）は、会社側の担当者が自分の文を調べる道具。
  相手の名前や自社の連絡先が入るのは普通で、自動で伏せると判定・書き換えの質が落ちる。
- 一方で、担当者が「送る前に個人情報を消したい」場面もある。

## 決定

- ツールの自由入力は、既定では伏せずに Jev・Claude に送る。
- 各ツールの入力欄に「個人情報チェック」を置く。
  - 規則と、設定で「Kev で判定する」がオンのときだけ Kev（または MOCK）で調べる。Jev・Claude には送らない。
  - 結果はモーダルで出す（入力欄を動かさない）。「個人情報マスク」で入力欄を【種類】に置き換え、送る内容を本人が確かめられる。
- 返信前チェックを運用の件から開いたとき（`?item=`）は、問い合わせをサーバ側で件の本文から作り、伏せる。
  - 受付の確認で決めた個人情報（人が足した分も含む）と、規則の候補をすべて伏せる。
  - 画面から来た問い合わせは使わない（`item_id` を送り、サーバが置き換える）。入力欄は読み取り専用にし、「伏せ字済み（受付の確認どおり）」と出す。
- 方針・判定の指摘は会社の文なので伏せない。

## 結果

- 良い点: ツールの判定・書き換えが、実際の文面どおりに働く。お客様の本文は、ツールからでも受付と同じ扱いで守られる。
- 悪い点: 担当者が自由入力にお客様の個人情報を貼ると、そのまま外に出る。個人情報チェックのボタンを押すかは本人任せ。
  社内の規程で「外部送信の前に必ず伏せる」とする場合は、既定を「伏せる」に切り替える設定を足す。
