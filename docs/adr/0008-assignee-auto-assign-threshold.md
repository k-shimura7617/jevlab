# 0008. 担当者は確信度が高いときだけ自動で割り当て、人の割り当てを例として学ばせる

- 状態: 採用
- 日付: 2026-09-26
- 関連: [jev.md §6](../jev.md#6-このプロジェクトで使ったパターン)

## 背景と課題

エスカレーションの件を誰が対応するかを決める作業を減らしたい。
ただし、誤った割り当ては対応の遅れにつながる。担当者の在席状況（受付中など）を毎回入力するのは、運用の負担になる。そのため、この案は採らなかった。

## 検討した選択肢

1. すべて人が割り当てる
2. モデルの推定で常に自動割り当てする
3. **確信度が閾値以上のときだけ自動で割り当て、それ以外は推定を表示して人が決める**

## 決定

選択肢 3 を採用する。

- **推定の仕方:** 担当者の ID をキーにした Choice で推定する。「どれでもない」も含める。
  - 選択肢の説明には、名前・所属・担当範囲を書く。
  - 最近の対応例（件の見出し）も添える。
- **推定のタイミング:** 仕分けと同じ問い合わせで、推測として聞いておく。エスカレーションになった件だけに使う。
- **自動割り当ての条件:** 確信度が閾値（既定 0.7）以上のときだけ。
- **対応例に使う件:** 次の 2 つを満たす件だけ。
  - 人が割り当てて完了した件（自動で割り当てたままの件は、推定の答えそのものなので除く）。
  - 個人情報の確認で「送ってよい」と判断済みの件（見出しは候補をすべて伏せる）。
- **当たり具合の表示:** 人が担当を決めた件だけで、推定の一致率と、取り違えの多い組み合わせを出す。

## 結果

- 良い点
  - モデルを学習させずに、担当範囲の書き方と対応例で精度を上げられる。
  - 取り違えの組み合わせが、担当範囲の見直しの手がかりになる。
- 悪い点
  - 担当者の数だけ選択肢の説明が増え、トークンが増える（例の見出しは 24 字まで、例は 1 人 3 件まで）。
