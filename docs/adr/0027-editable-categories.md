# 0027. 分類と振り分け先のチャンネルを設定で編集できるようにする

- 状態: 採用
- 日付: 2026-09-26
- 関連: [ADR-0013](0013-slack-socket-mode.md)

## 背景と課題

- 分類は「問い合わせ・クレーム・お礼・その他」の 4 つで固定だった。現場では「配送」「請求」など自分たちの分け方で振り分けたい。
- 分類の説明は Jev の質問（Choice）にそのまま入るので、説明を変えると判定の意味が変わる。変える前の件を正解に混ぜると、閾値の調整が狂う。
- 使った分類を消すと、過去の件の表示や集計が壊れる。

## 決定

- 設定に分類の一覧を持つ。項目は表示名・説明（Jev が読む）・チャンネル（#…）・使う。内部のキーは作ったときに決め、変えない。
- 使った分類は削除できない。「使う」を外して廃止にする（過去の件では「（廃止）」を付けて表示）。使っていない分類は削除できる。
- どれにも当てはまらないときの受け皿の分類を 1 つ決める（必ず「使う」）。使う分類は 9 個まで（数字キーで確定できる数）。
- 件ごとに、仕分けたときの分類の定義の版（使う分類のキーと説明から作る）を記録する。閾値の調整は、既定でいまの版の件だけで数える（「定義を変える前の件も含める」で全件）。
- チャンネル名を変えたら、Slack のチャンネルの対応付けも新しい名前に移す。
- 分類ごとに「返信不要」を選べる（既定はお礼だけ）。返信不要の分類で自動で振り分けになった件は、チャンネルに投稿し、✅ を付けて自動で完了にする（担当は割り当てない）。
  - 抜き取り確認に選ばれた件は、人が見るまで完了にしない。
  - 自動で完了にした件は人が見ていないので、閾値の調整の「人が確認した件」には数えない。
  - 問い合わせ・クレーム・その他は、返信の漏れを防ぐため、従来どおり人が完了にする。

## 結果

- 良い点: 現場の分け方で振り分けられる。説明の書き換えを評価の歪みなしに試せる。
- 悪い点: 定義を変えた直後は、閾値の調整に使える件が減る。評価ダッシュボード（mail アプリ）の分類は固定のまま。
