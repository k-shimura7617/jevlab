# 0030. 利用者の画面を 4 つに絞り、細かい設定と試験の機能は管理画面に移す

- 状態: 採用
- 日付: 2026-09-27
- 関連: [ADR-0006](0006-priority-in-code.md)、[ADR-0007](0007-human-in-the-loop-queues.md)、[ADR-0018](0018-business-hours-sla-single-reminder.md)、[ADR-0027](0027-editable-categories.md)

## 背景と課題

- 使う人は CS 担当とリーダーで、エンジニアではない。
- 画面に機械学習の実験用のつまみ（確率・割れの幅・例の件数など）が並び、左のメニューは運用だけで 11 項目あった。
- 対応目安・優先度の重み・抜き取り確認・デモの進め方など、使われ方を決める前に足した機能が多かった。
- 細かい調整は利用者ではなく開発側が請け負う（有償のカスタム開発）方が、使いやすく、仕事にもなる。

## 決定

- 利用者のメニューは 4 つにする。
  - 受付箱: 全件。担当者で絞る。
  - 対応待ち: 個人情報の確認・分類の確認・エスカレーションをタブでまとめる（URL は変えない。Slack のリンクを壊さないため）。
  - 成績: 分類の混同行列と、おすすめの確信度に合わせるボタン。担当の推定の当たり具合。
  - 設定: 分類（分類とチャンネル・自動で振り分ける確信度・個人情報の 2 つのオンオフ）、担当者、Slack。
- 入口（`/ops`）は、残りの件数と片づける画面へのリンクだけにする。
- 管理画面（`/admin`）に、開発側が使うものを移す。メニューには出さない。
  - 処理の状況（受信シミュレータ・お客様としてメールを送る・処理フロー）、詳細設定、個人情報の判定、コネクタ・ファイル取り込み、疑似 Slack、監査ログ。
- 次の機能は外す。
  - 対応目安・営業時間・休業日・担当未定の知らせ（ADR-0018 を廃止）。
  - 優先度の重みと表示（ADR-0006 を廃止）。確認待ち・エスカレーションは届いた順（古い順）に並べる。
  - 抜き取り確認（ADR-0007 の一部を廃止）。成績の正解は、人が確定・完了した件から取る。
- 人に回す条件（強い不満・緊急・確信度が低い・判断が割れる・個人情報）は、いまの動きのまま固定する。値は管理画面で変える。
- 保存済みの設定に残る古い項目は、読み込むときに無視する。

## 結果

- 良い点: 利用者は、何をすればよいかを入口の件数で分かる。設定の画面で迷う項目が減る。
- 悪い点: 対応の期限を知らせる仕組みがなくなる。要るときは、使う業務に合わせて開発側で作る。

## 追記（2026-09-27）

- 管理画面も左のメニューに出す（利用者の要望）。管理画面の上のタブは、メニューと重なるので外した。
- ファイル取り込みは利用者も使うので、管理画面のコネクタから外し、設定の「取り込み」タブ（`/ops/import`）に移した（左のメニューを増やさないため）。取り込んだ後は、運用ダッシュボードの処理フローに移って進み具合を出す。
- 入口の見出しは「対応が必要な問い合わせ N 件」にし、処理フローも入口に出す（管理画面から移した）。空のときは「すべて対応済みです」。
- 空の一覧は「〜はすべて済みました」「すべて対応済みです」と書く（「件はありません」では何のことか分からないため）。
- 受付箱と対応待ちの 3 画面は、一覧と詳細を画面の下端まで伸ばし、中でスクロールする（件数やタブで枠の大きさが変わらない）。
