# 0023. 並行の作業は git の worktree と PR で分ける

- 状態: 採用
- 日付: 2026-09-26
- 関連: [ADR-0012](0012-staging-copy-during-user-testing.md)（これを置き換える）、[handoff.md](../handoff.md)

## 背景と課題

- リポジトリを GitHub（`k-shimura7617/jevlab`）で管理し始めた。
- 利用者は Claude Code の Web セッションでも PR を作り、main にマージしている。ローカルの Claude Code とも並行で作業する。
- 利用者はローカルの `scripts/dev.sh`（8000・5173）で動作確認を続けている。

## 決定

ADR-0012 のコピーによるステージングをやめ、git で分ける。

- 作業を始める前と区切りごとに `git pull origin main` する。
- 実装は worktree（別の作業ツリー）のブランチで行う。利用者の作業ツリーでは直接編集しない。
- PR を作り、セルフマージしてよい（2026-09-26 に利用者が許可）。main へ直接 push はしない。新しいセッションでは、最初に許可が続いているかを確かめる。
- 別のセッションが同時に触っているファイルは避ける（利用者が教える）。
- 反映で起きること（自動の再起動・画面の再読み込み・`uv sync`）は、先に 1 行で伝える。
- `docs/` は区切りごとに更新する。

## 結果

- 良い点: 差分と履歴が git に残り、戻すのも 1 コマンドになる。複数のセッションが並行できる。
- 悪い点: 同じファイルを複数のセッションが触ると衝突する。着手前の取り込みと、担当ファイルの分担が要る。
