# 0025. 担当の推定が閾値に届かなくても、仮で割り当てる

- 状態: 採用
- 日付: 2026-09-26
- 関連: [ADR-0008](0008-assignee-auto-assign-threshold.md)（一部を置き換える）、[ADR-0013](0013-slack-socket-mode.md)

## 背景と課題

- ADR-0008 では、推定した担当の確率が閾値（既定 0.7）以上のときだけ自動で割り当て、残りは人が決めることにした。
- 実際に使うと、担当未定の件がエスカレーションに残った。担当が 1 人でも、「該当なし」が選ばれたり確率が低かったりして割り当たらない。
- Slack で当番に「担当を決めてください」と書いても、誰も割り当てないまま残りやすい。

## 決定

- 自動の割り当てがオンなら、担当中の人のうち、推定の確率が一番高い人に必ず割り当てる。「該当なし」が一番でも同じ。担当が 1 人ならその人。
- 確率が閾値以上なら「自動」、届かなければ「仮」とする（`assign_provisional`）。画面では「仮」と表示する。
- Slack の返信には「仮」と書かない。本人をメンションし、担当確信度を 1 行で添える（確信度の数字で、仮かどうかは読み取れる）。
  - 当初は Slack でも「仮」と書く案だったが、メンションの文面を短くするため外した（PR #44・#45）。
- 返信の要る件は、振り分け済みの件にも同じように割り当ててメンションする（PR #44）。返信のいらない分類（お礼など）は割り当てない。
- 人が割り当て直すと「仮」は外れる。推定の当たり具合は、これまでどおり人が割り当てた件だけで測る。

## 結果

- 良い点: 担当未定のまま放置される件がなくなる。
- 悪い点: 確率の低い推定でも本人が呼ばれる。違っていたら人が割り当て直す手間が要る。
