# 0005. 項目の抽出は「生成」ではなく「候補から選ばせる」

- 状態: 採用
- 日付: 2026-09-26
- 関連: [jev.md §6](../jev.md#6-このプロジェクトで使ったパターン)

## 背景と課題

問い合わせから、注文番号・希望日や期限・金額を取り出したい。
LLM に値を書かせると、本文にない値を作ったり、形式が崩れたりすることがある。

## 検討した選択肢

1. LLM に値を生成させる
2. 正規表現だけで取り出す（候補が複数あると、どれが用件の対象か決められない）
3. **正規表現で候補を拾い、候補の文字列そのものを Choice のキーにして、「どれでもない」を足して選ばせる**

## 決定

選択肢 3 を採用する（公式の value extraction の cookbook と同じ形）。

- 候補は、出現順で重複を除き、最大 254 件とする。
- 選ばれたキーが候補にない場合（想定外の応答）は、値なしとして扱う。
- 仕分けと同じ問い合わせに、質問を足すだけで済む。

## 結果

- 良い点
  - 本文にない値は出ない。
  - 候補が複数あっても、用件の対象を選べる（購入日と到着希望日を区別するなど）。
- 悪い点
  - 候補の取りこぼしは、モデルでは補えない。正規表現の網羅性を、データで確かめる必要がある。
