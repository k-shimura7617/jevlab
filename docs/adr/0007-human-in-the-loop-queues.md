# 0007. 人の確認は目的別の 3 つの待ち行列と、抜き取り確認で行う

- 状態: 採用
- 日付: 2026-09-26
- 関連: [0004](0004-threshold-tuning-not-finetuning.md)

## 背景と課題

モデルが迷う件、業務上人が見るべき件、個人情報の扱いを決める件がある。
これらは、確認する人も、見るべき点も違う。

## 決定

目的の違う 3 つの待ち行列に分け、画面も分ける。

| 待ち行列 | 入る条件 | 人がすること |
| --- | --- | --- |
| 個人情報の確認（`pii_review`） | 個人情報を検出した・迷う候補がある・見落としの疑いがある | マスクする箇所を確かめ、マスク / ブロックを決める |
| 分類の確認（`review`） | 分類の確信度が中間（確認の閾値以上、自動の閾値未満） | 分類を確定する（キー操作で速く） |
| エスカレーション（`escalated`） | 確信度が低い・強い不満・緊急・ブロックした件 | 担当を決めて対応し、完了にする |

- 自動で振り分けた件の一部（既定 5%）は抜き取りで人が確認する。その結果は、正解として閾値の調整に使う。
- まとめて処理（一括）を用意する。件ごとに成否を返し、途中で失敗しても残りを止めない。

## 結果

- 良い点
  - 人の手間を、判断が必要な件だけに集められる。
  - 確認の結果が、次の閾値の調整に使える正解になる。
- 悪い点
  - 待ち行列が 3 つあるので、全体の滞留は運用ダッシュボードの流れ図で見る必要がある。
