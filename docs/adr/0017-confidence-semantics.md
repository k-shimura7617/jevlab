# 0017. 確信度は Jev の公式の定義で扱い、判断が割れた件は人に回す

- 状態: 採用
- 日付: 2026-09-26
- 関連: [jev.md](../jev.md)、[research/jev-video-proposals.md](../research/jev-video-proposals.md)、[ADR-0007](0007-human-in-the-loop-queues.md)、[ADR-0008](0008-assignee-auto-assign-threshold.md)

## 背景と課題

Jev の紹介動画で、確信度の定義が分かった。

- Choice の確信度は最大の確率そのものではない。選択肢の数 N で補正した値 `(p_max − 1/N)/(1 − 1/N)`。
- Score の確信度は `max(0, 1 − D/B)`。両端に割れると 0 になり、四捨五入した段階は真ん中に見える。

これにより、次の 3 つの問題があった。

- 不満度を四捨五入した段階で判定していたため、割れた件が自動で振り分けられうる。
- 担当者の推定は、人数（N）が変わると閾値の意味が変わる。
- MOCK は確信度＝最大確率だったため、閾値の練習が本物と違って見える。

## 決定

- **強い不満:** 不満度が「2」の確率が既定 0.35 以上ならエスカレーションする（`classify.strong_frustration_at`）。
- **判断が割れた件は人の確認へ回す:** 確信度が高くても、次の件は分類の確認に回す。
  - 分類の上位 2 つの確率の差が既定 0.1 未満の件（`classify.split_margin`）
  - 不満度が両端に割れている件
- **担当の自動割り当て:** 推定した担当の確率で判定する（N に依存しない）。確率が取れないときは自動で割り当てない。
- **MOCK:** 公式の式で確信度を計算する（`core/confidence.py`）。

## 結果

- 良い点: 割れた件が自動で流れない。閾値の意味が人数に左右されない。MOCK での練習が本物に近い。
- 悪い点: エスカレーションと分類の確認が以前より増える。
