# 0015. 既存の問い合わせのファイルを取り込み、過去分で導入前に試算する

- 状態: 採用
- 日付: 2026-09-26
- 関連: [ADR-0004](0004-threshold-tuning-not-finetuning.md)、[ADR-0002](0002-kev-pii-guardrail.md)

## 背景と課題

- 現場の問い合わせは、共有メール（Outlook が主）、Excel の管理表、ヘルプデスク（Zendesk など）、Slack にある。どのツールも CSV は出せるが、日本語の Excel の CSV は多くが Shift_JIS。
- 取り込みは UTF-8 の CSV（差出人・アドレス・件名・本文）だけで、過去の分類も使えなかった。
- 導入してよいかを、自社の過去の問い合わせで先に数字で見たい。

## 決定

- **ファイルはサーバで、標準ライブラリだけで読む。** CSV（UTF-8・Shift_JIS を自動で見分ける）、.xlsx、.eml・mbox、Slack のエクスポート（.zip）。依存は増やさない。
  - .xls・.msg・.pst は読まない（.xlsx・CSV・.eml で保存してもらう）。
- **表は列の対応を画面で決める。** 過去の分類の列は、値ごとに jevlab の分類に当てる（名前から推測し、人が直せる）。
- **過去の問い合わせは「試算用」として取り込む（`backfill`）。**
  - 仕分け（Jev）まで行い、振り分けの結果だけ残して完了にする。投稿・Slack・担当の割り当て・人の確認には回さない。
  - 個人情報は人が確認しないので、候補をすべて伏せる（規則だけ。Kev は使わない）。ブロックの方針の種類があれば Jev に送らない。
  - 過去の分類は `expected` に入れ、閾値の調整で「想定ラベル・過去の分類」を選ぶと、閾値ごとの自動化率と誤り率が出る。
  - 運用の集計・人が確認した正解（閾値の調整の「人」）には入れない。

## 結果

- 良い点
  - 現場の形式のまま取り込め、導入前に自社のデータで自動化率と誤り率を見られる。
  - Slack・人の対応に過去分が流れ込まない。
- 悪い点（引き受けたこと）
  - 試算の件も Jev の料金がかかる（1 件あたり約 $0.0001）。
  - 候補をすべて伏せるので、実運用より伏せすぎの本文で判定する。
  - 1 ファイル 20MB・5,000 件まで。大きいものは期間などで分けて書き出す。
