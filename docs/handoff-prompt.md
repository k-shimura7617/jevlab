# 引き渡し用のプロンプト

新しいセッションの最初に、下の枠の中をそのまま貼ってください。

```
jevlab（GitHub: k-shimura7617/jevlab）の作業を引き継いでください。
前のセッションの会話は見られない前提で、リポジトリの資料だけを正として進めます。

## 前提
- 作業環境: ローカル（~/develop/2026/jevlab）か、クラウドのセッションか。最初にどちらかを確かめる。
  - クラウドのセッションからは、私のサーバ（8000・5173）と Kev（8009）には届かない。画面や Slack の設定は私の手元で行う。
- Kev は別リポジトリ ~/develop/2026/kev で私が起動する（jevlab の中では動かない）。
- ブランチで作業し、PR を作ってセルフマージしてよい。ただし、この許可が続いているかを最初に私に確かめる。main へ直接 push しない。

## 最初にすること（この順で）
1. リポジトリ直下の CLAUDE.md を読む。
2. docs/handoff.md を全部読む（特に 2 章「利用者の方針」、7 章「やることリスト」、8 章「既知の落とし穴」）。
3. docs/walkthrough.md で、画面ごとの動きを把握する。
4. git pull origin main する。画面をビルド（cd frontend && npm ci && npm run build）してから uv run pytest -q で全件通ることを確かめる。ビルドしていないと tests/test_web.py の 1 件が 503 で落ちる。
5. 読み終えたら、次の 3 つを短く報告して、私の指示を待つ。
   - 理解した方針（5 行以内）
   - やり残しの一覧（1 項目 1 行）
   - 次に手を付ける候補 1 つと、その理由 1 つ

## 必ず守ること（要点。詳細は CLAUDE.md と handoff.md の 2 章）
- 敬語で、簡潔に。締めの要約や、聞かれていない指摘は付けない。
- 細かい判断はそちらで決め、理由を 1 行添える。私に聞くのは方針に関わるものだけ（推奨を添える）。
- ボタン名・見出しは私が決めた名前を使う。カッコ書きを付けない。画面は固定枠にする。
- 実際の Jev（課金あり）と Kev の起動は私が行う。検証は MOCK で、別ポート（8010）と別の JEVLAB_VAR_DIR で行う。私のサーバには触らない。
- .env と .env.example は読まない・触らない。
- 運用の問い合わせは、マスク前の本文を外部（Jev・Claude・Slack）に送らない。
- 区切りごとに docs/ を更新し、完結したレポート（何をしたか・使い方・検証結果・残り）を出す。
```
