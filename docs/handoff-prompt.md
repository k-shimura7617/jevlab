# 引き渡し用のプロンプト

新しいセッションの最初に、下の枠の中をそのまま貼ってください。

```
jevlab（GitHub: k-shimura7617/jevlab）の作業を引き継いでください。
前のセッションの会話は見られない前提で、リポジトリの資料だけを正として進めます。

## 最初にすること（この順で）
1. リポジトリ直下の CLAUDE.md を読む。
2. docs/handoff.md を全部読む。特に次の 3 か所は必ず読む。
   - 2 章「利用者の方針と、これまでに注意されたこと」
   - 7 章「次にやる（このセッションのやり残し）」
   - 8 章「既知の落とし穴」
3. docs/walkthrough.md で、画面ごとの動きを把握する。
4. git fetch し、main を --ff-only で最新にする。uv run pytest -q で全件通ることを確かめる。
5. 読み終えたら、次の 3 つを短く報告して、私の指示を待つ。
   - 理解した方針（5 行以内）
   - やり残しの一覧（1 項目 1 行）
   - 次に手を付ける候補 1 つと、その理由 1 つ

## 必ず守ること（要点。詳細は handoff.md の 2 章）
- 敬語で、簡潔に。締めの要約や、聞かれていない指摘は付けない。
- 確信がないことは「確認できていない」と書く。訂正は訂正だけ。
- 私の案を否定する前に、意図を確認する。
- ボタン名・見出しは私が決めた名前を使う。勝手に言い換えない。カッコ書きを付けない。
- 画面は固定枠にする。開閉や結果の表示で、ほかの欄やボタンの大きさ・位置を変えない。
- 複数の文の説明は句点で改行する。「〜そう」のようなふんわりした言葉は使わない。
- 実際の Jev（課金あり）と Kev の起動は私が行う。検証は MOCK か Kev で、別ポート（8010）と別の JEVLAB_VAR_DIR で行う。私のサーバ（8000・5173）には触らない。
- .env と .env.example は読まない・触らない。
- マスク前の本文を Jev に送らない。外に出る見出しは個人情報の候補を伏せる。
- 区切りごとに docs/ を更新し、完結したレポート（何をしたか・使い方・検証結果・残り）を出す。
- コミット・push・PR・マージは、このセッションで許可が続いているかを最初に確かめてから行う。
```
