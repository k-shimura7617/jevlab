### 2.2 Confidence（確信度）の定義 — 新規・重要

公式ドキュメント（docs.typesafe.ai/confidence）の説明をスライドで解説していた。

- **Choice**: `C = (p_max − 1/N) / (1 − 1/N)`（N: 選択肢の数、p_max: 最大確率）
  - 例: N=3、p_max=0.90 → 0.850。N=3、p_max=0.55 → 0.325
  - 一様分布（どれも 1/N）で 0、1 つに集中して 1。**同じ最大確率でも、選択肢の数 N によって確信度が変わる。**
- **Score**: `C = max(0, 1 − D / B)`
  - D: 最大確率の段階からの距離の期待値（ばらつきの度合い）。例: 段階 0,1,2 に 0.90/0.05/0.05 → D = 0.15
  - B: 基準値（段階の中央からの平均距離。3 段階なら (|0−1|+|1−1|+|2−1|)/3 = 2/3）
  - 例: 0.90/0.05/0.05 → C = 1 − 0.15/(2/3) = 0.775。0.55/0.05/0.40（両端に割れる）→ D = 0.85 → **C = 0**
- Noul には確信度がない（値そのものが P(yes)）— 既知。理由の補足（46:30 付近の議論）: Noul は暗黙に 2 択の Choice で、
  N=2・p_max=0.8 でも確信度は 0.6 にしかならない。P(true) をそのまま見る方が直感に合う。
- 公開されている計算式で確率から計算した値と、応答に付いてくる confidence は、0.001 程度ずれることがある（丸めでは説明しきれない差。実用上は同じと見てよい）（45:30 付近）。
- 複数選択（A と B の両方を選ぶ）は Choice ではできない。**選択肢ごとに Noul で聞き、しきい値を超えたものを採用する**（47:30 付近）。
- 質疑での案: Score の確信度は「最大確率の段階から離れた段階に確率がある」ほど下がるので、`1 − 確信度` をリスクの指標として使う考え方もある（48:30 付近）。
- 公式の立場: 確信度は「分布が 1 つに集中しているか」を表す便利な指標の 1 つにすぎず、この定義に固定されない。
  **評価の仕方によっては別の指標の方が適するので、独自の確信度が欲しければ確率（probabilities）から自分で計算すればよい。**
- 所感（10:40 付近）: 微妙な問題は最大確率が 54% のように低くなりがちで、確率が低く割り当てられた問題は正解率も低い傾向がある。
  → 低いものを人が見る（ヒューマン・イン・ザ・ループ）運用が成り立つ。

| 新規 | 「選択・段階・Yes/No として定義できる」は、向いているというより**前提条件**。強みが出るのは、State で周辺の文脈（問い合わせ本文に加えて、そのユーザーの情報など）を渡して判断させるとき（53:00 付近） |

## 3. jevlab にとっての意味（要点）

- 確信度は「最大確率」ではなく、選択肢の数 N と分布の形で決まる。閾値は N を固定した上で決めるか、最大確率など自前の指標で判定する。
- Score は期待値を丸めた段階だけを見ると、両端に割れた判断を見落とす。段階ごとの確率か確信度を併せて見る。
- Noul は「成立」寄りに偏ることがあり、否定形との整合も保証されないので、問いの向き（問題を yes にするか）を揃え、質問ごとに閾値を測る。
- 実行ごとに少し揺らぐので、閾値付近の件は人の確認に回す運用（jevlab の「分類の確認」）が理にかなっている。判定結果は件ごとに保存して監査できるようにする（jevlab は保存済み）。
